# 疑難排解

## 先學會看紀錄

出問題時有三個地方可以查，由快到慢：

**1. 執行項目**（Apps Script 左側 ⏱ 圖示）

列出所有執行紀錄，**點任一列會展開完整內容**。從 LINE 打進來的 `doPost` 也在這裡。

特別注意「部署」欄：

- `上端` = 編輯器裡的最新程式碼
- `版本 N` = 部署出去的快照

**如果 `doPost` 顯示的版本號不是最新的，代表你改的東西還沒生效。**

> 編輯器下方那個「執行記錄」面板有時候不會即時更新，看「執行項目」比較準。

**2. 試算表的「系統紀錄」分頁**

所有錯誤都會寫進去，包含 Gemini 回傳的完整原始訊息。

**3. 內建診斷函式**

在函式選單直接選來執行，都只在編輯器跑，**不用重新部署**：

| 函式 | 用途 |
|---|---|
| `顯示紀錄表網址` | 找不到試算表時印出網址 |
| `顯示儀表板網址` | 印出儀表板網址（含金鑰） |
| `檢查Gemini模型` | 列出你的 key 現在能用哪些模型 |
| `測試Gemini` | 直接打一次，印出完整網址與回應 |
| `測試模型速度` | 用真實任務比較各模型的秒數與判斷正確性 |
| `測試每日推播` | 預覽早報內容，不會真的傳出去 |
| `檢查學校行事曆` | 檢查行事曆匯入得對不對 |
| `測試問行事曆` | 不透過 LINE 直接測問答 |

## 常見狀況

### 改完程式碼沒生效

**最常見的問題。** 編輯器改的是「上端」，LINE 打到的是「部署快照」。

**部署 → 管理部署作業 → 鉛筆 → 版本選「新版本」→ 部署**

只按「部署」但版本沒換等於原地踏步。到「執行項目」看 `doPost` 的版本號有沒有跟著跳，就知道成功了沒。

---

### LINE 完全沒反應

依序檢查：

1. **「執行項目」裡有沒有新的 `doPost`？**
   - 沒有 → LINE 沒打進來。檢查 Webhook URL 還在不在、Use webhook 有沒有開、按 Verify 看結果
   - 有，狀態「失敗」→ 點開看錯誤訊息
   - 有，狀態「已完成」但你沒收到 → 看下一點

2. **LINE 官方帳號後台的「自動回應訊息」關了嗎？** 沒關的話它會搶著回罐頭訊息。

3. **系統紀錄分頁有沒有 `LINE reply 失敗`？** 有的話 C 欄會寫原因，常見是 reply token 過期（處理太久）。

---

### Gemini 回 404

錯誤訊息會直接寫明原因，通常是：

> This model is no longer available to new users. Please update your code to use models/xxx

模型被 Google 退場了。執行 **`檢查Gemini模型`** 看你的 key 現在能用哪些，把 `00_Config.gs` 的 `GEMINI_MODEL` 改成清單裡的名稱。

### Gemini 回 503

> This model is currently experiencing high demand

那個模型一時塞車。程式內建備援機制會自動改用 `GEMINI_MODEL_備援` 重試，兩個都不通才會失敗。常常發生的話就把主、備兩個模型對調。

### Gemini 回 400

多半是模型不接受某個參數。看系統紀錄裡的完整訊息，`INVALID_ARGUMENT` 通常指向 `generationConfig` 裡的設定。

---

### 回覆要等 20～30 秒

Gemini 3 系列的一般模型會先「思考」再回答。執行 **`測試模型速度`** 比較各模型，選秒數短而且「拆出」欄位正確的。

實測 lite 系列通常快 10 倍以上，判斷品質沒打折。

> 注意：`thinkingBudget: 0` 會被拒絕（400），`thinkingLevel: low` 實測也沒幫助。**換模型比調參數有效。**

---

### 語音說格式不支援

`04_Line.gs` 裡把 `'audio/mp4'` 改成 `'audio/aac'`，重新部署。

### 圖片讀不準

- 拍照時盡量正面、光線足，避免反光
- iPhone 的 HEIC 格式：LINE 傳出去通常會自動轉 JPEG，還是出錯的話把相機設定改成「相容性最佳」
- **內容看得懂但判斷怪怪的** → 那是提示詞要調，改 `02_Gemini.gs` 的 `媒體描述_`

---

### 每天早上沒收到推播

1. 必須先在 LINE 傳過至少一則訊息（程式才知道你的 userId）
2. 左側「觸發條件」確認 `每日推播` 還在
3. 執行 `測試每日推播` 看內容產不產得出來

---

### 日期抓錯

確認 `appsscript.json` 的時區是 `Asia/Taipei`。

---

### 授權跳不過去

- **「Google 尚未驗證這個應用程式」** → 點左下「進階」→「前往…（不安全）」→ 允許。這是正常的，自己寫的腳本都會這樣
- **「這個應用程式遭到封鎖」且沒有「進階」可點** → 學校 Workspace 管理員限制了，改用個人 Gmail 帳號
- **新增功能後突然沒權限** → 有些功能會用到新的權限（例如存雲端硬碟）。在編輯器執行一次會用到該權限的函式，過了授權再重新部署

---

### 儀表板打不開／看不到資料

- 網址要帶 `?k=金鑰`，沒帶只會顯示一行狀態文字。執行 `顯示儀表板網址` 重新取得
- 某一區塊掛掉不會拖垮整頁，但該區會消失。到系統紀錄找 `儀表板區塊失敗`

---

## 還是解決不了

把這三樣貼出來，通常就能定位：

1. 「執行項目」裡那筆失敗紀錄**展開後的完整內容**
2. 試算表「系統紀錄」分頁的最後幾列
3. `doPost` 那筆的**部署欄**寫什麼版本
